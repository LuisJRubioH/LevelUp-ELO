## Problem and correction

When both players had answered every item, the last responder returned from the ASGI handler
without a WebSocket close frame. A native client saw an abnormal close (browser code 1006).
The other player's handler could remain waiting for another answer even after `game_end`.

`api/websocket/pvp.py::_finish_match` now sends both results, then closes the connected sockets
normally (1000), inside its existing single-close guard, **only if both players answered every
item**. A competing finisher waits until that close completes. The answer loop also waits for
the guarded close instead of attempting another read on a completed, fully answered match.

The scope is transport cleanup for spec 007 FR-002 / US1-AS1. Scores, rating arithmetic,
persistence, match timing and admission rules are unchanged. A timed-out incomplete match keeps
ignoring late answers as its existing characterization test requires. Account-expiry abandonment
keeps its separate close code (spec 004 FR-052).
